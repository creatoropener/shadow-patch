P2P/stream transfer cannot be decrypted — IV seed is never sent to the receiver
createEncryptionStream/createDecryptionStream in lib/crypto/stream-cipher.ts are meant to be a matched pair: encrypting a byte stream then decrypting the resulting frames with the same key should reproduce the original bytes. It doesn't — decryption throws an AES-GCM authentication error on the first chunk. The encoder derives each chunk's IV from a random 12-byte seed generated once per stream; the frame format only carries plaintext length and chunk index, never that seed, so the decoder can't reconstruct the same IV. Reproduce by piping plaintext through createEncryptionStream(key), collecting the frames, piping them through createDecryptionStream(key), and asserting the recovered bytes equal the original — including a final partial chunk. Fix without changing either function's signature or breaking the decoder's ability to handle frames split at arbitrary byte boundaries.
generateSessionKey() returns { raw, key } — use the .key field as the CryptoKey, not the return value itself.

The same missing-seed defect exists in P2PSender/P2PReceiver (lib/transfer/p2p.ts), the live WebRTC transfer path advertised on the homepage — fixing the pattern here should carry over to that code too, though it's out of scope for this issue's test (WebRTC isn't available in the test runtime).
